# Proposal

## Why

第 4 课已经能把本班材料切片检索，并在有依据时生成带出处的单轮回答。第 5 课要求把「提示词」从班级级挪到**智能体**上：教师在本班创建智能体，为它配角色提示词、绑定技能与本班材料；学生选定一个智能体后连续追问，服务端按该智能体选技能、检索并**流式**返回回答。为此需要新增智能体 / 技能 / 会话三组数据与接口、一次回答的技能路由与消息组装、SSE 流式输出，并提供可对照试调的 OpenAPI/Swagger 与接口自动化测试。

## What Changes

- **新增智能体（`tutor_agents`）与两份绑定（`tutor_agent_skills`、`tutor_agent_materials`）。** 教师在本班创建、修改、启停智能体，并绑定本班技能与本班材料；班内名称唯一（≤64 字），角色提示词 ≤2000 字且为空时回退默认角色设定（不因此拒绝请求）；学生列表只返回已启用者；跨班按编号访问一律按「不存在」返回 404。绑定是关联表而非快照，教师改绑定后下一次提问即生效。
- **新增技能（`skills`）与文件解析。** 技能以单一文本文件定义：空行以上是元数据（`名称`、`适用条件`、`资料`、`工具`、`启用`），空行以下是引导正文；服务端解析后入库并保留整份原文（`source_text`）便于取回再编辑。校验：名称 / 适用条件 / 启用必填，名称班内唯一（≤32 字）、适用条件 ≤120 字、说明 ≤2000 字、资料 ≤32 字、文件 ≤8000 字；`工具` 只接受 `knowledge_search`；重复字段、未定义字段、空行以下缺正文均在提交时拒绝并返回可读错误。写操作仅教师。
- **新增会话与消息（`conversations`、`messages`）。** 新建会话时必须选定本班一个已启用智能体，`agent_id` 写入后不再变更（换智能体要新开会话；本班无已启用智能体时返回 400）；标题新建为占位串「新的提问」，首轮提问后改为其前 24 字（截取为空则保留占位串），此后每轮只刷新 `updated_at`。历史窗口固定为按写入顺序的**末尾 6 条**消息、每条正文截断 **500 字**，角色非 `user`/`assistant` 或正文为空的记录跳过。会话与消息均为私有资源，按用户与班级双重过滤，跨用户 / 跨班 / 不存在返回完全一致的 404。
- **新增技能路由。** 候选集只含该智能体绑定且已启用的技能；把 `适用条件` 按中英文逗号、顿号、分号、竖线切词后与提问做**大小写折叠的子串匹配计分**，取最高分；同分取技能编号较小者；零分即不选技能。一次提问**至多命中一个技能**（不调用模型、不做语义匹配）。
- **新增消息组装与证据口径。** 系统消息只放：智能体提示词（空则默认角色）、当前技能名称与说明、以及固定边界句；命中名称含「解题引导」的技能时追加「先判对错并指出错在哪一项、不写得数 / 选项 / 完整解题过程」的硬性要求。检索资料编成编号后放进**用户消息**（`[n] 材料《标题》切片 k` + 正文，每条截断 800 字，先剔除空正文 / 学科不符再连续编号）。有资料时要求用 `[n]` 标注；**检索落空仍照常作答**，引用列表为空、正文剥掉所有 `[n]`，且不得整段回「资料中未找到相关内容」。
- **新增 SSE 流式回答。** `POST /api/conversations/{id}/messages` 以 `text/event-stream` 逐段返回，事件分四类：`meta`（状态、本次技能、引用列表，最先到达）、`delta`（本次**新增**文本）、`done`（助手消息编号，落库之后）、`error`（流开始后失败）。响应头含 `Content-Type: text/event-stream`、`Cache-Control: no-cache`、`Connection: keep-alive`、`X-Accel-Buffering: no`，每帧显式 `Flush`；第一个事件产生时才写 200，此前可返回 401/400/404/503。助手消息连同引用列表与技能名一并落库。
- **文档与测试。** 用处理器注解生成 OpenAPI 描述并挂载 `/openapi.json` 与 `/swagger/index.html`（文档路由在业务路由之前注册，路径与注册一致）；新增 `apitest/`：一个接口一个脚本、目录按 URL 组织、`run_all.py` 一键跑完并生成 HTML 报告（报告不提交 Git），除状态码外核对返回内容与数据库一致。
- **前端。** 新增智能体管理、技能管理、会话列表与新建、聊天页；聊天页用 `fetch` 提交 POST 并自行按 `event:` / `data:` 解帧逐段渲染，引用列表先到即显示，结束后可打开引用材料。

## Capabilities

### New Capabilities

- `tutor-agents`: 智能体的数据模型、教师管理与启停、角色提示词与回退、技能 / 材料的绑定语义、班内名称唯一与跨班 404。
- `ai-skills`: 技能文件的格式与解析校验、字段与长度约束、`knowledge_search` 工具白名单、原文保留、教师增删改查与启停、班内名称唯一。
- `conversations`: 会话与消息两张表的职责、会话锁定智能体、标题生成、末尾 6 条 / 每条 500 字的历史窗口、私有资源与跨班 / 跨用户隔离。
- `streaming-chat`: 技能路由（候选集、词法计分、至多一个）、系统 / 用户消息组装、有依据与无依据两种口径、引用编号规则、SSE 四类事件与工程细节、助手消息落库与可回溯。
- `api-docs`: 由处理器注解生成 OpenAPI 描述、`/openapi.json` 与 `/swagger/index.html` 的挂载与路径一致性、按文档试调主要接口。

### Modified Capabilities

- `web-frontend`: 页面范围扩展到智能体管理、技能管理与会话选智能体；聊天页以 `fetch` 解帧逐段渲染 SSE 并展示引用，前端仍不承担访问控制。
- `model-gateway`: 对话网关新增**流式**补全能力（服务端消费网关的流式响应并转推 SSE 事件），保持地址 / 密钥 / 模型配置与回退规则不变。

## Impact

- **数据**：新增 `tutor_agents`、`tutor_agent_skills`、`tutor_agent_materials`、`skills`、`conversations`、`messages` 六张表；建表幂等，并对班级 A 预置两条「解题引导」种子技能（数学 / 语文）。`class_prompts` 不在本次范围（回答路径只读智能体提示词）。
- **接口**：新增 `GET/POST /api/agents`、`GET/PUT /api/agents/{id}`、`GET/POST /api/skills`、`PUT/DELETE /api/skills/{id}`、`GET/POST /api/conversations`、`GET /api/conversations/{id}`、`POST /api/conversations/{id}/messages`（SSE）、`GET /openapi.json`、`GET /swagger/index.html`；既有 `POST /api/ask`（固定文案口径）与 `POST /api/search`（本班范围）保持不变。
- **客户端网关**：对话网关需支持流式 chat completions；服务端消费增量并转推 `delta`，不向后端模型传工具。
- **依赖与构建**：新增 Go OpenAPI 注解生成工具（计划 `swaggo/swag` + Swagger UI 静态资源）与生成步骤；SSE 使用标准库，无额外运行时依赖；数据层 / 检索 / 网关配置沿用第 4 课。
- **编排**：Nginx 对 SSE 关闭 `proxy_buffering` / `proxy_cache`、读超时放宽到 120 秒，服务端补 `X-Accel-Buffering: no`；密钥仍只放本机 `.env`，不入库、不进镜像、不提交 Git。
- **测试**：新增 `apitest/`（一接口一脚本 + `run_all.py` HTML 报告），覆盖登录、检索、提示词 / 技能、建会话并发一条消息，并核对数据库。
- **非目标**：不实现 WebSocket、断线续传或双向实时；不引入 LangChain / Dify 等编排框架；不做 Agent Skills 的 `SKILL.md` / YAML frontmatter 规范；不做语义路由或交叉编码器重排序；不向模型注入实际工具调用（`knowledge_search` 仅为入库字段）。
