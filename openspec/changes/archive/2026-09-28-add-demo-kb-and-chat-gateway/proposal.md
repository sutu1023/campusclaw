# Proposal

## Why

可追溯检索与问答链路已经实现，但缺少可演示、可验收的数据与引导：当前种子材料每班仅一段占位正文、未触发切片与向量入库，界面也没有示例问句；同时对话网关未配置，`/api/ask` 无法端到端演示。为了让课堂演示、逐条验收与新用户上手不依赖外部数据准备，需要一份内置的演示知识库与示例问句，并让对话网关复用嵌入网关的同一 API。

## What Changes

- **对话网关复用同一 API**：当 `CHAT_BASE_URL` / `CHAT_API_KEY` 未显式配置时，回退使用 `EMBEDDING_BASE_URL` / `EMBEDDING_API_KEY`；`CHAT_MODEL` 指定对话模型（默认 `course-chat`）。网关仍只由服务端调用，密钥不下发浏览器。
- **演示知识库**：随种子预置一组演示材料，班级 A 与班级 B 各若干篇、正文充实、主题明确；每篇含上传原文并触发切片与向量入库，使 keyword / vector / hybrid 检索与 `/api/ask` 均可命中。
- **班级可区分的演示数据**：每班演示语料含仅本班出现的专属主题/词，用于演示与验收班级隔离。
- **示例问句**：系统经服务端提供一组示例问句（可由演示语料回答），并至少包含一条无依据问句；在检索与问答界面展示，点击即以该问句发起查询。
- **文档**：README 增加演示知识库、示例问句、对话网关配置与可复现样例查询说明。

## Capabilities

### New Capabilities

- `demo-knowledge-base`: 面向检索与问答演示/验收的预置知识库（班级可区分、可检索、带出处）、系统提供的示例问句，以及可复现的样例查询与预期结果。
- `model-gateway`: 对话网关与嵌入网关复用同一 API（未显式配置时回退到嵌入网关的地址与密钥），使 `/api/ask` 在演示环境可端到端运行。

### Modified Capabilities

（无。`knowledge-retrieval` 与 `web-frontend` 的主规格尚未归档，故本变更以新能力承载演示语料、示例问句与网关复用行为。）

## Impact

- **配置**：`internal/config` 增加对话网关对嵌入网关的回退；`.env.example` 与 README 更新。
- **种子数据**：新增多篇 `materials` + `knowledge_entries`，并在启动时为未索引材料触发切片与向量入库；重复启动保持幂等。
- **接口**：新增 `GET /api/examples` 返回示例问句（需登录）。
- **前端**：检索与问答界面展示示例问句并可一键发起查询。
- **验收**：新增演示语料检索（三模式）、班级隔离、问答引用与无依据样例的可复现记录。

## Non-goals（非目标）

- 不做多轮对话、流式输出或会话编排。
- 不新增嵌入/对话供应商，不改变现有鉴权、班级隔离与检索算法。
- 不引入外部数据集或联网下载语料；演示语料为内置示例。
- 不改变数据库表结构（复用现有 `materials` / `knowledge_entries` / `knowledge_chunks`）。
